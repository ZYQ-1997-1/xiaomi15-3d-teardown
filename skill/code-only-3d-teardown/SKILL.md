# Code-only 3D Teardown

把真实产品的官方图、尺寸和参数，变成一张可以点击拆解、旋转查看、离线打开的 3D 网页。

核心原则只有一句：**先量比例，再建模；先做部件和交互，再做氛围。**

## 0. 开始前先定契约

先确认四件事；缺哪一项就向用户问，不要凭印象补：

1. **产品与参考图**：至少一张正面/背面图和一张尺寸图；有官方参数页更好。
2. **交付形态**：源码目录 + 单文件 HTML？是否需要离线、是否需要移动端？
3. **可拆部件清单**：用户希望哪些部件能单独拆下；芯片、摄像头、电池等是否需要独立。
4. **素材授权**：官方图、品牌字标、屏幕壁纸、芯片贴纸能否放入公开仓库。不能确认时，执行第 8 节的素材隔离方案。

若用户连续纠正比例，不要继续“目测微调”；停下来用第 1 节的方法量像素。

## 1. 从官方图量真实比例

不要凭感觉调整模组大小、开孔位置或整机厚度。用已知尺寸做标尺：

- 从官网拿到真实长度/宽度/厚度，例如 `152.3 × 71.2 × 8.08 mm`。
- 在参考图上量机身像素宽 `P_phone` 和某部件像素宽 `P_part`。
- 真实尺寸：`real_part = P_part / P_phone × real_phone_width`。
- 位置也要量：左/上边距 = 像素边距 / 标尺。
- 面积大的部件（相机岛、副屏、散热口）尤其要先算，再写几何参数。

可复用脚本与示例：`references/measurement.md`。

一个真实案例：Xiaomi 15 的相机岛约 **43 × 43.5 mm**，占 71.2 mm 机身宽约 **60%**；最初按 3.35 × 3.62 cm 做会明显偏小。这个案例的完整修错记录在 `references/case-study-xiaomi15.md`。

## 2. 选择离线优先的技术栈

默认使用：

- **Three.js** 单个经典脚本（暴露 `window.THREE`），不要用 `import`，这样 `file://` 双击也能开。
- 原始 **HTML + CSS + JavaScript**，不用打包器；页面必须零网络请求。
- 所有贴图用 **Canvas 绘制** 或 **data URL 内嵌**；不要依赖远程图片。
- 构建一个单文件版本：CSS、Three.js、数据、模型、应用、内嵌图片全部 inline。

如果上游 Three.js 只有 ESM 版本，先转成经典脚本：

- 参考 `scripts/build-three.mjs`。
- 生成后检查 `window.THREE` 是否存在，而不是直接改 `vendor/three.js` 的 import 行。

单文件打包参考 `scripts/build-single.mjs`。要点：

- 用回调形式的 `String.replace`，避免 Three.js 源码里的 `$&` 被当作替换模式。
- 内嵌 `<script>` 前转义 `</script`。
- 构建后断言外部 `<script src=...>` 数量为 0。

## 3. 代码结构：数据、几何、应用分离

推荐四层：

```text
data.js   产品参数、部件元数据、爆炸向量、锚点、修复难度
model.js  纯几何/材质/Canvas 贴图，返回 Three.Group
app.js    场景、光照、轨道控制、拾取、UI、标签、动画循环
index.html + css/style.css
```

每个部件至少要有：

```js
{
  id, index, name, en, category, accent, tag,
  fixed,                 // 中框等不可拆基准
  explode: [x, y, z],    // 爆炸位移
  rotateY,               // 需要翻面展示的部件
  anchor: [x, y, z],     // 3D 标签锚点
  offset: [x, y],        // 2D 标签偏移
  repair, repairText,
  specs: [{ k, v }],
  desc
}
```

所有部件按 id 注册到 builder map；构建时自动创建 **pivot**，把几何移到部件包围盒中心，这样旋转不会绕整机原点甩出去。

## 4. 程序化建模的可靠套路

- **圆角板**：`Shape + ExtrudeGeometry`，bevel 自适应；不要固定 bevel，否则小孔会塌。
- **环形/开孔**：`Shape` 加 hole，或 `RingGeometry`、`TorusGeometry`；镜头、按键、扬声器孔都适用。
- **玻璃/金属**：`MeshPhysicalMaterial`；玻璃用 clearcoat、低 roughness、适度 envMapIntensity，不要用高饱和 emissive 假装反光。
- **贴字/图标**：CanvasTexture；透明背景；注意 `colorSpace = SRGBColorSpace`。
- **屏幕壁纸/品牌图/芯片贴纸**：如果用户提供图片，用 data URL 内嵌；纹理加载是异步的，记得在 `img.onload` 后设 `needsUpdate`。
- **不要逐个镜头做凸起**，除非官方图确实如此。相机岛通常是一整块凸起，内部镜片与玻璃齐平。
- **圆角要跟中框一致**：相机岛、后盖、屏幕盖板的 corner radius 要同步检查。
- **字标方向**：先在官方竖屏背面图上确认是横排还是竖排；需要横持阅读的字标要旋转 90°。
- **顶部/底部开孔**：从底部边框图和官方尺寸图逐个确认；不要为了“对称”补孔。
- **重复部件**：移动/替换零件后全局搜索旧变量名（如 flash、mic），确认没有遗留的第二个几何。

## 5. 交互和 UI

- 自研 OrbitLite 或 OrbitControls 均可；必须支持拖拽旋转、滚轮缩放、移动端 pinch。
- 点击部件：拾取 → 爆炸/收回；双击空白恢复；右键/Shift 平移可选。
- 每个部件有 3D 锚点 + DOM 标签 + SVG 引线；标签要避让、不能压住左右面板。
- 细节面板包含：部件编号、名称、英文名、类别、规格行、描述、维修难度、拆下/装回、定位。
- 移动端：侧栏改为浮层，详情改为底部抽屉；顶部保留部件清单入口。
- 拆解进度用 `可拆部件数` 动态计算，不要写死数字；新增部件后自动更新。
- 悬停玻璃/大件时，优先用**反射增强**或柔和玻璃高光，不要叠高饱和色块和矩形包围框。

## 6. QA：用无头浏览器验收，不靠肉眼

QA 至少要断言：

1. 控制台/`pageerror` 为零。
2. 轨道旋转和缩放确实改变相机参数。
3. 点击任意部件能触发爆炸，进度到 `N/N`。
4. 爆炸态标签数量 = 可拆部件数；标签之间、标签与左右面板之间无重叠。
5. 恢复后所有部件回到 0；重新加载没有残留。
6. 移动端 390×844：部件清单、详情抽屉、爆炸视图不溢出。
7. 单文件 `file://` 打开时，外部请求数 = 0。

可复用启动器：`scripts/qa-browser.mjs`。不要硬编码作者机器的绝对路径；用 `CHROME_PATH`、`PLAYWRIGHT_MODULE` 或项目内依赖。

## 7. 打包与发布

- 运行时零 npm 依赖；`vendor/three.js` 本地化。
- 生成单文件 `dist/<Product>-3D-Teardown.html`，构建后验证没有外链。
- README 至少包含：截图、在线/本地打开方式、项目结构、操作说明、参数来源、许可与第三方素材声明。
- 公开仓库必须区分：
  - **代码**：MIT/Apache 等；
  - **品牌/产品素材**：小米、徕卡、骁龙等商标与官方图通常不属于代码许可，需要单独声明，不能宣称“全部 MIT”。
- 可加 GitHub Pages workflow：把 `index.html`、`css/`、`js/`、`vendor/`、`assets/` 发布为静态站点。

## 8. 素材隔离与可再分发方案

如果公开仓库没有素材授权：

1. 把用户提供的屏幕图、字标、贴纸放入 `assets/`，但不纳入代码许可证。
2. 在 `THIRD_PARTY_NOTICES.md` 写清权利归属和“仅用于演示”。
3. 页面保留 fallback：删掉 `js/*-image.js` 后仍能用 Canvas 占位图运行。
4. 更彻底：把品牌图替换成自制中性占位图，再公开仓库。

## 9. 本案例的修错清单（防止重犯）

- 先做大了相机模组，再被用户指出仍偏小；最后按官方图量到 43×43.5mm、占宽 60% 才正确。
- 闪光灯曾同时存在“模组内”和“模组外”两个；修正后只保留右侧靠上一条独立竖条。
- 相机模组曾经有一层矩形反光平面，在圆角模组上露出直角边；移除矩形 overlay，改由材质/柔和纹理表现。
- 顶部曾被加了麦克风孔，但实机顶部无孔；以官方边框图为准删除。
- 字标曾用系统字体近似，字形不对；最终直接使用用户提供的字标图，去背成透明 PNG。
- 后盖 hover 曾用高饱和紫色 emissive + 包围框，效果怪异；改为中性玻璃材质 + 环境反射/柔和斜向高光。
- 部件数量会变化：新增可拆芯片后，列表、进度、加载文案、顶部计数、QA 全部要同步。
